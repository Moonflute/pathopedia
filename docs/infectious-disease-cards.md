# 감염질환 카드 작성·연결 규칙

259개 질환 카드의 편집 원본은 `content/diseases/`이며 장기별·감염군별 16개 파일로 나뉜다. `data/library.json`은 빌드 때 생성한다.

## 수록 범위

병원체의 감염·증식·침입·독소 작용이 중심인 질환과 감염성 임상 증후군. 잠복감염은 활동성 질환과 구분한다.

증상만 있는 항목·단순 집락화·비감염성 염증·감염 후 면역질환·병원체 관련 종양은 독립 감염질환 카드로 넣지 않는다. 세균성 감염이 확인되지 않은 유방 염증이나 무균성 췌장 괴사도 별도 감염 카드와 구분한다.

## 카드 필드

| 필드 | 용도 |
| --- | --- |
| `id`, `name`, `englishName`, `searchAliases` | 표시명과 한영 검색. ID는 이름 변경에도 유지한다. |
| `category`, `entityType`, `anatomicSites`, `transmission` | 분류·장기·경로를 독립된 코드로 관리한다. |
| `summary` | 20–160자의 임상 특징 한두 문장. 뒤쪽 필드를 자르지 않고 직접 작성한다. |
| `clinical` | `presentation`, `diagnostics`, `management`, `redFlags`의 짧은 상세 설명. |
| `etiologies` | 연결할 병원체의 `pathogenId` 또는 별도 영문 이름·`domain`, 적용 맥락. |
| `treatments` | 약제 구성·적용 상황·우선/대안/조건부·단독/병합/순차와 전체 요법/구성 성분 구분. |
| `supportiveCare` | 작성자가 명시한 대증·지지치료 여부. 약제 요법과 별도 데이터이며 빈 목록으로 추론하지 않는다. |
| `relatedDiseaseIds` | 관련 질환·임상형을 명시한 연결. |
| `sourceIds`, `localReferenceNotes` | 내부 검토·보충을 위한 출처와 원본 노트 경로. 카드 UI에는 노출하지 않는다. |

## 약제 표시

각 요법은 `rank: preferred | alternative | conditional`, `mode: single | combination | sequence`와 명확한 `context`를 갖는다. `coverage: component`는 전체 요법의 일부임을 뜻하며 뒷면에도 표시한다. 금색은 현재 선택한 우선요법의 구성 약제에만 적용한다. 대안·조건부 선택은 흰색이며 다른 임상 상황의 약제는 회색이다. `role: adjunct`인 보조 약제는 우선 항균제로 금색 표시하지 않는다.

MSSA/MRSA, 경험요법/표적요법, 경증/중증, 감염 부위, 임신·면역저하, 감수성·지역 내성, 유도/공고/유지 등의 맥락을 한 질환의 일괄 1차 약제로 섞지 않는다. 용량표나 전체 처방은 이 카드 데이터의 범위에 포함하지 않는다.

`etiologies`와 `treatments`는 작성자가 직접 지정한다. 게임용 감수성 관찰이나 `REGIMEN`만으로 질환 적응증·우선순위를 추론하지 않는다. 데이터에 없는 약제·원인균은 영문 이름으로 남겨 거짓 카드 ID를 만들지 않는다. 기존 약제의 제형·경로가 달라지는 경우 치료 상황에 이를 명시한다.

`supportiveCare: true`인 질환은 치료 사이드에 흰색 의료 십자와 짧은 ‘대증’, 앞면 하단과 뒷면 치료 항목에 ‘대증치료’를 표시한다. 기존 관리 설명과 항균제 선택 조건·노출 후 예방·중환자 지원 등은 그대로 유지한다. 면역억제 조정·면역 회복·병변 처치·내시경/충체 제거, Dexamethasone 중심의 크룹 치료는 빈 약제 목록만 보고 대증치료로 바꾸지 않는다.

## 생성과 재사용

`scripts/compile-diseases.mjs`가 ID·분류·출처·연결·치료 모드를 검사한다. `scripts/seed-cards.mjs`는 공유 카탈로그에 `diseases`, `diseaseCategories`, `diseaseRoutes`, `diseaseEntityTypes`를 넣고 병원체·약제의 `diseaseIds` 역참조를 같은 원본에서 생성한다. `content/diseases/schema.json`과 `data/library-schema.json`을 외부 소비자도 사용할 수 있다.

`createCardCatalog(db).disease(id)`가 표시 내용을 반환하고 `createCardModels(data, db).disease(id, treatmentId)`가 현재 상황의 작은 기호·빛·경로를 구성한다. 표시 코드가 의료 문장을 분석해서 속성을 만들지 않는다. 앞뒤는 기존 2:3 카드 틀을 공유하며 중앙 SVG 장기·감염군 기호는 나중에 그림만 교체할 수 있다.

## 출처 보관

19 the medicine resource의 노트와 감염 경로 JSON을 읽기 전용으로 참고했다. `docs/disease-source-audit.json`에 원본 데이터·참고 노트의 상대 경로와 SHA-256을 기록했다. 추가 공공 자료는 `content/diseases/index.json`의 `references`에 기록한다. 출처·근거 수·기록 수는 카드 앞뒤·호버에 표시하지 않는다.
