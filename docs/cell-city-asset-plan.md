# Cell City 마을과 방어전 에셋 활용 계획

작고 귀여운 중세풍 마을에 생산·운송·수리 작업이 보이고, 병원체 침입 때 성벽과 전초기지의 전투·손상·복구가 드러나는 방향으로 구성한다. 세포와 장기의 정체성을 유지하면서 중세 주택·시설·방어선의 외형을 조합한다.

계획 기준은 2026년 10월 21일의 코드 v0.57.0과 `cell-city-assets`에 보관한 8개 팩이다. 아래 단계는 향후 적용 순서이며, 모델별 최종 채택은 동일한 조명과 카메라에서 색감·형태·작업 공간을 비교한 뒤 결정한다.

## 외관 기준

- 크림색 석재, 민트색 지붕과 설비, 따뜻한 목재색을 기본으로 한다. 구역별 장기 색상과 세포의 역할 색상은 식별 표식으로 남긴다.
- 집·작업대·벽은 두툼한 형태와 무광 표면으로 맞춘다. 모델의 축척과 원점을 정규화하고, 긴 벽은 일정한 크기의 패널을 반복해서 구성한다.
- 항구·가공소·수로·공방의 역할 표식과 설비를 남긴다. 새 건물이나 가구가 장기별 특징, 작업자의 손동작, 재고 표식과 선택 표시를 가리지 않게 배치한다.
- 세포와 병원체는 기존의 생물 캐릭터 표현을 발전시킨다. 중세풍 장비는 세포의 역할을 읽게 하는 소품과 시설 외형에 사용한다.
- 평시에는 생활과 생산, 경계 시에는 초소와 보급, 전투 시에는 명중과 장벽 손상, 복구 시에는 인부와 자재가 눈에 들어오게 한다. 감염은 오염·변색으로, 화염은 심한 시설 피해의 게임적 표현으로 구분한다.

## 구역별 활용안

### 피부 성벽과 전선

기존 피부 성벽 14구간과 세 전선인 피부·호흡기·소화기의 역할을 유지하면서 외형을 보강한다. 성벽은 현재의 부드러운 크림색 석벽을 기준으로 문·목재 보강·기단·잔해를 조합한다. 정원 울타리는 마을 내부의 구역 경계로, 높은 목책은 전선의 방어 시설로 구분한다.

| 상태 | 표현 | 연결할 실제 상태 |
| --- | --- | --- |
| 정상 | 연속된 벽과 닫힌 방어선 | 장벽 HP 75% 이상 |
| 손상 | 같은 벽의 균열 표식·빠진 패널·작은 잔해 | 장벽 HP 0 초과 75% 미만 |
| 파손 | 통과 가능한 틈과 낮은 잔해 | 장벽 HP 0 |
| 복구 대기 | 작업 표식과 비어 있는 자재 자리 | 수리 주문이 있으나 자재·인부가 미도착 |
| 복구 작업 | 도착한 자재, 작업자, 진행도에 따른 보강 | 기존 배송·작업자·수리 타이머 |

복구가 끝난 문·벽은 기존 진입 판정과 동시에 닫힌다. 화면 앞쪽 성벽을 낮춰 보여주는 기존 카메라 처리를 새 모듈에도 적용한다. 호흡기 출입구와 점액·섬모 설비의 공간은 확보하고, 장식용 문이 임의의 새 병원체 경로를 만들지 않게 한다.

Roadside의 추가 후보는 다음과 같다. ZIP 내부 루트는 `Fences and walls glb/`다.

| 파일 | 삼각형 | 활용안 |
| --- | ---: | --- |
| `EA_Env_Prop_Wall_StonePalisade_Wall_01a.glb` | 1,139 | 방어선 보강 모듈의 비교 후보 |
| `EA_Env_Prop_WoodenGate_04a.glb` | 160 | 작은 목문 또는 차단 시설의 부품 |
| `EA_Env_Prop_Wall_StoneWallBroken_01b.glb` | 544 | 파손 구간의 낮은 잔해 후보 |
| `EA_Env_Prop_Fence_Ranch_02a.glb` | 338 | 공방·창고 주변의 짧은 구역 경계 |

같은 계열이어도 완성된 정상·손상·파손 세트로 단정하지 않는다. 기본 벽의 크기와 색을 정한 다음 파손 부품의 바닥·폭·빈틈을 맞추고, 필요한 상태 변형을 구성한다. 긴 반복 벽판은 현재의 단순한 형태를 기반으로 하고 1,139삼각형 모듈은 소수의 보강 지점에서 비교한다. 14구간 전체에 고밀도 완성 벽을 여러 장씩 반복하지 않는다. 9,595삼각형의 `EA_Env_Prop_Fence_Watchtower_01a.glb`는 초기 대상에서 제외하고, 초소는 기존 기둥·지붕과 가벼운 부품의 조합으로 보강한다.

Kitchen 경로의 루트는 `Restaurant_Godot/Models/`, Farm은 `Farm Pack/Models/`다. 이동·장전·제조·수리의 기준점은 기존 `workStation`과 작업 대기열이다. 새 가구는 이 위치에 맞춰 배치하며, 통로와 작업자의 손이 닿는 공간을 확보한다. 시설 이동·회전 편집 시에는 소품도 같은 소유 구역과 함께 변환한다.

Food 팩은 `Food Full/GLB/Bag_3_A.glb` 166, `Bread_1_A.glb` 192, `Apple_2_A.glb` 206을 우선 후보로 둔다. 식품 종류는 자원의 시각적 변형에 사용하고, 별도의 농사·식단 시스템으로 연결하는 작업은 후속 기능으로 구분한다.

### 자연과 수로

Cute Park의 `Cute Park/gLTF/TreeCube_1_2.glb` 132, `Tree_2_1.glb` 244, `Bush_1_1.glb` 376, `StreetLamp_1_1.glb` 670을 우선 비교한다. 현재 장식 수의 상한 안에서 기존 소품과 교체해, 건물·세포·전투 위치가 잘 보이게 한다.

벤치는 Medieval의 249삼각형 모델을 기본으로 하고, Cute Park의 2,880삼각형 벤치는 강조할 장소의 후속 후보로 둔다. 분수도 박동 광장의 주요 설비를 가리지 않는 작은 강조물로 검토한다. 잔디·벽돌 텍스처를 추가로 요구하는 모델은 아틀라스만 쓰는 후보 뒤에 배치한다.

작은 다리는 Cute Park `Bridge_1_1.glb` 1,088삼각형부터 비교한다. Backroad는 `Gltf/EA_Walkway_Planks_02b_PRE.prefab.gltf` 138, `EA_arch_Bridge_Floor2_Wood_Clean_02b_PRE.prefab.gltf` 908, `EA_arch_Bridge_Floor1_Wood_broken_01d_PRE.prefab.gltf` 994를 후보로 둔다. 소형 판자 통로와 수로 부속물을 우선 사용하고 53,408삼각형의 대형 완성 다리는 초기 대상에서 제외한다.

초기 다리는 기존 수로와 이동 경로에 맞춘다. 다리 파괴에 따른 길 차단·재건·배송 우회는 별도의 시뮬레이션 기능이므로, 해당 기능을 만들기 전에는 파손 부품을 이동 경로 밖의 배경과 잔해에 사용한다.

Cute Dungeon은 `DUNGEON EXPORT/gLTF/Furniture/Floor_4_1.glb` 170, `Walls/Stairs_5A.glb` 34, `Walls/Pillar_3_1A.glb` 366을 기단·계단·방어 부품 후보로 둔다. `Walls/Wall_Door.glb`는 3,342삼각형과 12개 프리미티브를 포함해 초기의 작은 문 후보보다 후순위다.

### 전투와 피해 연출

- 기존 세포·병원체와 발사·명중·포식·치료 동작을 중심으로 전투를 표현한다. 인간 주민이나 대형 몬스터 모델을 새 인구로 추가하는 안은 기본 계획에 포함하지 않는다.
- 무기 팩의 활·방패는 방어 시설의 장식과 확대 관찰용 후보로 둔다. 다수 세포가 장비를 들 때는 기존 인스턴스 배치에 맞춘 경량 표현을 먼저 구성한다.
- 불꽃 36개·연기 24개라는 기존 전체 풀의 상한 안에서 모양·색·주기를 개선한다. 매 프레임 효과 객체를 생성하지 않고, 피해 위치와 실제 수리 상태에 따라 배치를 바꾼다.
- Cute Dungeon의 Unity 불 파티클은 표현 참고와 구성 확인에 사용한다. 실제 웹 효과는 현재 Three.js의 제한된 효과 풀에 맞춰 구성한다.
- 전투 소품과 작은 연기에는 그림자를 우선 생략하고, 벽·주요 건물·세포가 전투 위치를 읽게 한다. 화염의 발광은 색과 밝기로 표현한다.

## 리소스 준비와 잠정 목표

원본 ZIP은 `cell-city-assets`에 보관한다. 실제 반입 작업을 시작할 때 이 폴더를 Git 제외 대상으로 지정하고, 선택한 산출물만 `assets/city3d`에 둔다. 원본의 전체 FBX·Blender·미리보기·Godot 프로젝트 파일은 배포 모델 목록에 넣지 않는다.

내보내기는 선택 파일과 의존 텍스처를 허용 목록으로 관리한다. 팩·원본 ZIP 식별값·내부 경로·출처·이용 조건·산출물·축척·회전·원점을 기록하고, 같은 이름의 다른 팩 파일이 덮어써지지 않게 한다. 다리 glTF의 Godot 물리 확장 정보는 웹 게임의 진입·충돌 판정과 분리하고, 기존 시뮬레이션의 길과 장벽 상태를 기준으로 취급한다.

공원 GLB의 내장 이미지 138개는 고유 이미지 4개이고, 던전 320개와 음식 141개의 내장 이미지는 각각 한 이미지의 반복이다. 내보낼 때 이를 팩별 공유 이미지로 정리하고, 농장·주방·음식의 동일 색상표는 공용 리소스로 묶는다. 파일명과 재질 이름만으로 서로 다른 텍스처를 합치지 않는다.

다음 수치는 적용 전의 잠정 목표다. 동일한 카메라·도시 상태에서 측정한 비용에 따라 선택 모델과 배치 수를 조정한다.

| 항목 | 목표와 관리 방법 |
| --- | --- |
| 첫 묶음 파일 | 확인한 모델·의존 이미지 합계 약 1.18MB를 출발점으로, 상태 변형을 포함한 첫 반입은 2MiB 안쪽을 목표 |
| 후속 파일 | 구역 소품까지 포함한 선택 모델·이미지 누적 6MiB 안쪽을 목표로 관리 |
| 텍스처 | 주력은 공통 1024² 이미지. Medieval 건물의 추가 2K 벽·노멀맵은 해당 후보를 채택할 때만 포함 |
| 텍스처 메모리 | RGBA8과 전체 밉맵 가정 시 1024² 한 장 약 5.33MiB, 2048² 한 장 약 21.33MiB. 첫 Medieval 묶음의 추가 이미지는 약 5.33MiB |
| Roadside 이미지 | 울타리·다리의 별도 2K 이미지를 모두 상주시키면 두 장만 약 42.67MiB. 각 1K 축소판을 비교하고, 충족하지 못하면 사용 구역·상주 조합을 제한 |
| 표시 기하 | 첫 적용 뒤 같은 장면에서 렌더링 삼각형 증가 20% 이내를 목표. 원본 모델 수보다 배치 횟수와 그림자 비용까지 함께 계산 |
| 렌더 호출 | 첫 적용은 기준 장면 대비 증가 6회 이내를 목표. 동일한 재질은 정적 병합·인스턴스로 묶음 |
| 동적 표현 | 세포 96·배송 48·병원체 32의 기존 상한과 기존 화염·연기 풀을 기준으로 구성 |

렌더링 목표는 현재 60fps와 적응형 품질 조절이다. 목표 수치는 실기기 성능을 보장하는 값이 아니며, 큰 원본을 일괄 불러온 뒤 품질을 낮추는 방식보다 선택 모델과 상주 텍스처를 줄이는 데 우선순위를 둔다.

모델·텍스처 캐시가 원본 리소스의 수명을 소유하도록 한다. 마을 편집에 따른 재구성 때는 배치 인스턴스와 합친 기하만 교체하고, 화면을 나갈 때 공유 원본을 한 번씩 해제한다. 고정 소품은 재질·색상·투명도·양면 설정이 호환될 때 병합하고, 파손 상태와 움직이는 부품은 분리한다.

## 단계별 확인 범위

첫 반입에서는 기본 마을, 장벽 파손과 실제 수리 완료, 생산·배송 중 시설 이동·회전의 세 흐름을 중심으로 확인한다. 모바일 크기 기본 시점과 확대 시점에서 손동작·셀 선택·벽 가림·라벨·통로를 함께 본다. 같은 저장 상태에서 바꾸기 전후의 프레임 속도·삼각형·렌더 호출·요청 파일·텍스처 수를 한 번씩 비교하고, 실패하거나 새 문제가 생긴 부분만 다시 확인한다.

진행 구분은 준비 문서 작성 → 첫 비교 장면 → 작은 실제 구역 적용 → 범위 확장이다.

## v0.58.0 첫 적용

2026-10-21 사용자 요청에 따라 `신규 에셋 적용` 체크박스를 추가했다. 첫 방문은 체크 상태이며, 이후 선택은 도시 저장과 별도 키로 유지한다. 해제하면 기존 외관으로 돌아가고, 체크하지 않은 채 입장하면 새 모델을 요청하지 않는다. 다운로드 중 해제·화면 이탈과 로딩 실패 뒤 재시도도 처리한다.

Medieval 10종에 Park 나무·덤불 3종, Kitchen 작업대·병 2종, Farm 탱크 1종을 더한 16종을 반입했다. 보수 공방·재료·수레·휴식 벤치·생산 작업대·산소 탱크·입구 문·자연물·14개 방벽에 연결했다. 14개 방벽은 체력·수리 상태를 그대로 읽는 인스턴스이며, 화재·잔해·보급·세포·병원체는 기존 상태와 표현을 사용한다.

| 항목 | 첫 적용 결과 |
| --- | --- |
| 추가 모델·이미지 | 2,362,064바이트, 약 2.36MB(2.25MiB) |
| 공용 텍스처 | 1024² 3장, RGBA8+밉맵 가정 약 16MiB |
| 비교 장면 | 같은 저장 도시·시간 11:18·일시정지 상태에서 체크 전후 비교 |
| 렌더 호출 | 33회 → 37회, +4회 |
| 표시 삼각형 | 약 75k → 89k, 약 +19% |
| 확인 | 체크 전환·설정 유지·도시 보존·실제 GLB 파싱·방벽 파손/복구 매핑·공유 원본 수명·모바일 배치 |

렌더 수치는 로컬 브라우저의 같은 비교 장면 기준이다. 모든 기기의 프레임 속도를 보장하는 수치는 아니다. 원본 ZIP은 `cell-city-assets/`에 유지하고 Git에서 제외한다. 선택 산출물은 `assets/city3d/bundle/`, 재현 스크립트는 `scripts/import-city-assets.py`에 둔다. 나머지 팩은 후속 적용 후보로 보관한다.

## v0.59.0 건물 외형 확대

첫 적용은 작은 소품과 외곽 방벽 위주여서 마을의 주요 실루엣이 거의 그대로였다는 사용자 피드백을 반영한다. 체크 시 민가 11채를 두 종류의 목조·초가지붕 건물로 교체한다. 박동 광장은 긴 회관, 숨결 항구는 목조 풍차 탑, 영양 가공소는 창고·사일로·시장, 조혈 공방은 목조 건물, 항체 공방은 제조 초소, 정화 수로는 기존 수처리 설비와 목조 작업소를 조합한다. 14구간은 석벽으로 바꾸고 네 모서리의 원형 망루를 추가한다. 지면·언덕은 연두색, 길은 흙길 색으로 맞추고 산소·물류 보기에서 혈관 색을 표시한다. 세포·병원체·작업 지점과 생물학적 표식은 기존 상태를 유지한다.

추가한 파일은 Medieval의 `Building_1_2_A`, `Barn_2_A`, `Buidling_4_2_A`, `Tower_2_A`, `Castle_Wall`, `Castle_Tower`, `StallWooden_1_A`와 Farm의 `SM_Silos_1_D`다. 모두 이미 사용하는 세 장의 1024² 이미지에 연결된다. 전체는 24종·3,587,172바이트로 첫 버전보다 약 1.23MB 증가하며, 이미지 상주량 추산은 약 16MiB로 유지한다.

같은 저장 도시의 일시정지 비교 장면에서는 약 140k 삼각형·38회 렌더 호출로 측정했다. v0.58.0의 89k·37회보다 표시 기하가 늘었으며, 이는 주택과 주요 시설의 외형까지 교체한 결과다. 고정 외형은 계속 재질별로 병합하고 석벽과 망루는 두 개의 인스턴스 묶음으로 처리한다. 화면 앞쪽 성벽과 망루는 낮춰 보이고, 파손 구간과 해당 망루는 실제 HP에 맞춰 비운다. 체크 해제 시 모든 건물과 방어선의 기존 외관으로 복귀한다.
