# Cell City 세포 체험

City 3D의 **세포 체험**에서 현재 도시의 세포 하나를 탐험가로 직접 조종한다. 테마 2의 혈관 수로와 테마 1의 격자 대로에서 같은 9개 도구를 사용한다. 도구함 창이나 역할 선택 없이 하단 퀵슬롯에서 즉시 교체한다.

1인칭 버튼을 누르면 조감도에서 시작 위치를 클릭·터치한다. 선택 중에는 도시가 잠시 멈추고 지도 드래그·확대는 유지한다. 기존 건물·주택·외벽 충돌을 통과한 정확한 지점으로 인계받은 세포를 이동한다. 지붕 클릭은 화면에 보이는 표면을 검사해 뒤쪽 길로 잘못 진입하지 않는다. 드래그·두 손가락 제스처는 시작 클릭으로 처리하지 않는다. 취소·Esc는 세포를 인계받지 않고 이전 배속으로 돌아간다.

## 조작

| 행동 | PC | 모바일 |
| --- | --- | --- |
| 이동·시선 | WASD · 마우스, 방향키 | 왼쪽 조이스틱 · 화면 드래그 |
| 도구 교체 | 휠 / 1–9 | 슬롯 터치 / 좌우 스와이프 |
| 직전 도구 | Q | 슬롯 터치 |
| 맞는 도구 장착 | F | 대상 카드의 도구 버튼 |
| 도구 사용 | 클릭 / E 유지 | 선택한 도구 버튼 유지 |
| 다음 배송지 | R | 목적지 옆 ↻ |
| 점프 | Space | 점프 |
| 달리기 | Shift 유지 | 달리기 전환 후 이동 |
| 앉기 | Ctrl 유지 / C 전환 | 앉기 전환 |
| 확대 조준 | 우클릭 유지 | 조준 유지 |
| 메뉴 | Esc / P | Ⅱ |

Shoot의 `play-ui.mjs`와 `play-engine.mjs`에서 휠·숫자 슬롯·직전 장비·스와이프 패턴을 재사용했다. 도구 교체는 도시를 멈추지 않는다. 사용을 누른 채 바꾸면 한 번 놓은 다음 다시 눌러야 새 도구가 작동한다. 작은 화면의 퀵슬롯은 가로로 이어지며 선택한 슬롯이 자동으로 보인다.

PC는 진입·계속하기에서 포인터 잠금을 자동 요청한다. 브라우저가 거부하면 드래그로 시선을 조절하고 화면 클릭으로 다시 요청한다. 잠금 해제·화면 이탈은 일시정지한다. 도시로 돌아가면 이전 배속을 복구한다.

## 도구와 실제 도시 상태

| 슬롯 | 도구 | 동작 |
| --- | --- | --- |
| 1 | 포식 글러브 | 실제 병원체의 HP 감소·처치·잔해 생성. 항체·보체 지원과 에너지·공격 주기 적용 |
| 2 | 산소 캐리어 | 폐 적재 → 산소가 부족한 장기에 하역. 실제 장기 산소와 통계 증가 |
| 3 | 영양 보급함 | 장의 창고에서 최대 20 적재 → 다른 장기의 보급 한도까지 하역. 창고 자원 차감 |
| 4 | 복구 렌치 | 손상된 장기·조직 HP 최대 +8. 재료 1–2와 에너지 2 소모. 기존 공사 주문은 유지 |
| 5 | 잔해 흡입기 | 실제 잔해 제거·국소 청소, 최대 6 운반 → 신장 집하장 하역 후 기존 여과 과정에서 처리 |
| 6 | 혈소판 패치 | 파손 피부를 HP 25까지 응급 봉합. 폐 장벽 보호도 가능. 에너지 4 소모 |
| 7 | 항원 채집기 | 미접수 병원체·잔해에서 항원 채집 → 림프절 접수. 기존 후천 면역 과정으로 연결 |
| 8 | 지원 신호기 | 가까운 장기로 방어 집결·15초 지원. 에너지 10 소모, 6초 재사용 대기 |
| 9 | 진단 스캐너 | 실제 장기 HP·산소·영양 또는 조준한 병원체 HP 확인 |

화물은 도구별로 따로 보존한다. 산소·영양·잔해·항원을 운반하다 다른 도구를 써도 사라지지 않는다. 산소·영양·복구·봉합은 멈춰서 사용을 유지한다. 먼 목표는 현재 배치의 경로와 미니맵으로 안내하며, 실제 작업은 조준한 객체에만 적용한다. 자원·거리·대상·도구·재사용 대기·장애물은 실제 상태 변경 시 다시 확인한다.

기존 산소 설비 6곳·보급과 집하 상자 6곳·림프절 항원 작업대 1곳을 작업 지점으로 사용한다. 건물 점유와 겹치는 설비는 바깥의 접근 가능한 지점으로 안내한다. 조준한 시설·잔해·병원체·손상 조직에는 이름과 현재 상태가 표시되고, 필요한 도구가 다르면 F 또는 대상 카드로 장착한다. 가까이 있다는 이유만으로 작업하지 않는다. 시선을 떼면 진행이 끊기고, 사용을 누른 채 다른 객체로 옮기면 놓았다가 다시 눌러야 한다.

사용 중에는 기존 설비에 붙은 밸브·상자 뚜껑이 움직인다. 조준 테두리와 진행 막대는 실제 대상 위치에 표시하고 완료 시 물자 이동 효과를 낸다. 가까운 시설 표식은 최대 3개만 보여 준다. 테마 변경이나 저장 복원은 별도 시설 상태를 만들지 않고 같은 도시 객체를 다시 연결한다.

기존 호중구를 우선 인계받고 선택된 호중구·적혈구도 사용할 수 있다. 세포 종류와 원래 AI 화물은 유지하며 조종하는 세포의 AI만 잠시 멈춘다. 저장 복원은 정상 AI로 시작하고 `pilotInventory`의 도구와 화물은 보존한다. v0.71의 산소 전용 저장도 기본값을 보충해 읽는다.

건물·주택·외벽 충돌, 점프·달리기·앉기·조준과 30 Hz 카메라 보간을 유지한다. 모든 도구로 수로·대로·조직 사이를 이동한다. 가까운 병원체는 피해를 주며 심장 근처에서는 회복한다.

## 구성과 에셋

기존 MIT Three.js, Shoot 입력·SVG 패턴, 도시 에셋을 재사용했다. 외부 모델·텍스처·패키지는 추가하지 않는다. 휴대 도구는 공유 기하 4종으로 만든 57개 메시 중 손·소매 8개와 현재 도구를 합쳐 최대 15개만 표시한다. 도시 뒤에 깊이 버퍼를 비우고 별도 카메라로 손을 그려 수면이나 건물에 가려지지 않으며, 프레임 비용 집계는 두 렌더링을 합산한다. 목적지 고리 1개, 최대 100개 인스턴스 경로 점을 유지하고 시작 위치 표시에는 기존 구역 고리를 재사용한다.

## v0.75.0 — 1인칭 이동 장비와 물리 도구

| 조작 | PC | 모바일 |
| --- | --- | --- |
| 제트팩 켜기/끄기 | J | 상단 비행 |
| 상승 / 하강 | Space / Ctrl | 상승 / 하강 유지 |
| 지상·공중 돌진 | V | 돌진 |
| 견인 빔 | 0 · 클릭/E 유지 | 견인 슬롯 · 사용 유지 |
| 충격 방출기 | − · 클릭/E | 충격 슬롯 · 사용 |
| 도구 전환 | 휠 · 1–0 / − · Q | 슬롯 터치 · 좌우 스와이프 |
| 복귀 | Esc → 길로 복귀 | Ⅱ → 길로 복귀 |

제트팩은 현재 도구와 독립적이며 최고 고도 14, 상승 4.3, 비행 이동 5.4(달리기 7.5)이다. 연료 100에서 상승 9/초·이동 5/초·호버 3/초를 사용하며 지상/지붕에서 22/초로 충전한다. 연료 소진이나 비행 해제 시 하강 속도를 3.6으로 제한한다. 돌진은 0.2초·속도 12, 에너지 8, 재사용 2.2초다. 누른 채 자동 재발동하지 않는다.

견인은 거리 10 안의 조준 잔해를 실제 지상 경로를 따라 당긴다. 가까워지면 6칸 공용 잔해 화물에 들어가며 신장에 하역한다. 충격은 전방 4.5 안에서 벽에 가리지 않은 병원체를 최대 2.8만큼 밀고 0.65초 멈추게 한다. 에너지 12와 재사용 1.5초를 적용한다. 비행 중 작업·포식·충격은 수직 거리와 시야도 검사한다.

비행 자세·제트팩 상태·돌진은 일시 상태이며 화물·도구·연료는 저장된다. 비행 중 저장은 복사본에서 세포만 안전한 지상으로 옮기며 현재 비행은 유지한다. 종료·테마 변경 시에도 접근 가능한 지상에 반환한다. 낮은 천장에서 앉기를 풀어 머리가 끼지 않도록 공간을 확인한다. 모바일은 사용·돌진·상승·하강·달리기·조준의 2열 버튼을 유지한다.

검증: 기존 이동·운반·객체 작업 22개와 비행·실제 삼각형 충돌·얇은 벽 돌진·지붕 착지·연료 소진·저장·견인·충격 6개 테스트 통과. 낮은 턱 수정 뒤 비행·충돌 6개 재확인. 로컬 전체 빌드는 반복하지 않고 배포 워크플로에서 통합 테스트와 빌드를 확인한다. 자동 브라우저의 포인터 잠금은 지원되지 않아 드래그 대체 조작으로 확인한다.

브라우저 확인: 테마 2 수로에서 상승·호버·공중 돌진·충격 도구 사용, 테마 1에서 보행·모바일 상승/하강/돌진·복귀를 확인했다. 390×844와 844×390에서 버튼과 선택 슬롯이 화면 안에 표시된다.

## v0.78.0 — 현장 관찰·협력·전투·입체 이동

스캐너(9)는 12 이내의 실제 세포·운반체·시설·병원체·항상성 장기를 관찰한다. 세포의 현재 작업·목적지·화물·대기 원인과 세션 중 최근 활동 6건을 표시한다. 현재 존재하는 면역세포·병원체 카드로 연결하며, 도감은 도시를 일시정지하고 연다. 이력은 WeakMap에 보관하므로 저장 크기를 늘리지 않고 새로고침 시 다시 기록한다.

| 조작 | PC | 모바일 |
|---|---|---|
| 세포 관찰 | 9 → 클릭/E 유지 | 스캐너 → 사용 유지 |
| 관찰 대상 따라가기 | T | 관찰 카드의 따라가기 |
| 관찰 해제 | X | 관찰 카드 × |
| 지원·물자 인계 | 관찰 카드의 지원 도구 → E | 지원 도구 → 사용 |
| 그래플 부착·스윙 | G 유지, 놓으면 해제 | 그래플 유지 |
| 그래플 줄 감기·풀기 | Space / Ctrl | 점프 / 앉기 |
| 운반체 탑승·하차 | 가까이 조준 후 B | 가까이 조준 후 탑승 |
| 현장 소리 | 소리 버튼 | 소리 버튼 |

추적은 직접 이동·점프·돌진하면 해제하며 실제 통행 경로와 건물 충돌을 따른다. 빠른 적혈구도 따라갈 수 있도록 거리에 따라 추적 이동 속도를 조절한다. 퇴장·사멸·저장 복원으로 대상이 사라지면 관찰을 종료한다.

물자 인계는 먼저 스캔한 세포에게만 적용한다. 적혈구와 산소 최대 8을 주고받고, 영양 최대 3으로 세포 에너지를 회복하며, 대식세포가 운반하는 잔해를 남은 화물 용량까지 인계받는다. 인계 중 대상은 잠깐 멈추고 작업 해제 후 AI로 돌아간다. 섬유아세포의 전달 완료된 공사에 합류하면 실제 자재·에너지를 사용해 남은 공사 시간을 줄인다. 복구 작업은 실제 조직 HP를 회복한다. 호중구·대식세포에는 18초 협동 방어를 요청할 수 있고, 방어 인원은 가까운 위협을 분담한다. 관찰만 하거나 목표 밖에서 사용하면 자원은 바뀌지 않는다.

첫 슬롯은 면역 펄스건으로 바뀐다. 기존 저장의 `engulf` 슬롯 ID는 호환을 위해 유지한다. 사거리 18·주기 0.28초·발당 에너지 2이며, 실제 조준 광선과 가장 가까운 건물 표면이 명중을 결정한다. 항체·보체·피막·산소·영양 지원은 기존 도시의 피해 계산에 연결한다. 반동·발사광·탄흔·명중음이 실제 발사 성공에 반응한다. NPC의 포식·NET·항원 제시 등 기존 면역 역할은 유지한다. 플레이어 근처 병원체는 피막형의 느린 접근, 연조직 침범형의 예고 후 돌진, 막대형의 측면 접근, 그 외의 추적으로 전투 동작을 구분한다. 이는 생리 기전과 구분되는 게임 조작 표현이다. 공격 예고 중 색이 변하고 근접 타격 성공 때만 플레이어 HP가 줄어든다.

그래플은 26 이내·높이 0.9 이상의 실제 정적 삼각형에 부착한다. 줄 길이는 1.2–26이며 팽팽할 때 바깥 방향 속도만 제거해 접선 방향 운동량을 유지한다. 줄 감기·풀기, 놓은 뒤 관성, 벽·천장·도시 경계 충돌을 적용한다. 주요 시설 6곳의 기존 지붕 위에는 착지판과 노란 부착 가로대를 둔다. 운반체 탑승은 실제 배송 객체를 따라가며 화물이나 AI 소유권을 바꾸지 않는다. 이동·점프·배송 종료·충돌 시 하차한다. 그래플·탑승·추적은 저장하지 않으며 공중 저장·퇴장은 기존 안전 지상 반환을 사용한다.

실제 작업에 맞는 근거리 세포 표식·물자 입자, 감염→방어→청소→복구 및 물류 부족의 현장 고리를 표시한다. 주변 사건은 최대 2건만 HUD에 보여준다. 가까운 시설 2곳의 소리는 거리·방향·실제 가동 상태에 반응하고 Shoot의 합성 사격음을 재사용한다. 평소에는 관찰 패널과 불필요한 목적지 경로를 숨긴다.

시뮬레이션 시나리오에서 탐험 중에만 식사·소규모 호흡기 노출·운동·수분 섭취·휴식이 기존 항상성·유입 경로로 발생한다. 첫 변화는 탐험 35초 뒤, 이후 55–79초 간격이다. 진행 중인 감염이나 HP 70 미만 장기가 있으면 추가 노출을 생략한다. 메뉴의 현장 변화 ON/OFF로 중단할 수 있다. 조감도 단독 운영과 다른 시나리오의 감염 일정은 유지한다.

검증은 기존 1인칭 이동·작업 검사와 신규 현장 동작 검사로 한정한다. 신규 검사 10건은 두 테마의 관찰·추적·이력, 산소·잔해 보존과 원격 작업 거부, 공동 건설의 실제 비용·완료 조건, 원거리 사격·차폐, 그래플 제약·관성·저장, 운반체 화물 보존·종료, 방어 분담·공격 예고, 현장 변화 중단을 확인한다. 전체 테스트와 빌드는 GitHub Pages 배포 워크플로에서 수행한다.
