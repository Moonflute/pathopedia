# PATHOPEDIA

병원체 동정과 가이드라인 기반 항생제 선택을 복습하는 의사·의대생용 웹게임.
병원체·약제·감염질환을 같은 카드 틀로 열람하고 발견 기록을 모읍니다.
상단 메뉴는 **병원체 추측 · 항생제 선택 · defense · shoot · survival · re-roll · 카드 도감**의 일곱 탭입니다.

## 실행

Node.js 20 이상. 런타임 의존성이 없는 정적 ES module 앱입니다.

```sh
npm ci
npm run dev
npm test
npm run build
```

개발 서버: http://127.0.0.1:4173. 빌드 결과: `dist/`.
GitHub Actions가 main push 시 테스트 → 정적 빌드 → Pages 배포합니다.
저장소 Pages의 source는 GitHub Actions입니다. `/pathopedia/` 하위 경로에 호환됩니다.

## re-roll — 랜덤 디펜스

상단 **re-roll** 또는 `#reroll`에서 항생제 / 병원체 진영을 선택합니다. 항생제 14종 / 병원체 13종, 15칸 보드, 20웨이브와 보스 4종. 의학적 효능과 무관한 판타지 전투입니다.

- 골드로 소환하면 같은 종류·같은 별 2개가 자동으로 연속 합성됩니다. 최대 5성, 대성공은 별 +2. 클릭·탭은 기물 정보와 실제 사거리 표시, 드래그는 이동·자리 교환. 합성은 이동 후 수렴하며 3성 이상은 강화된 연출을 표시합니다.
- 일반·희귀·영웅·전설·신화 티어. 일반 소환은 12회 이내 희귀 이상 보장. 행운 뽑기는 기본 희귀 20% / 영웅 55% / 전설 23% / 신화 2%이며 행운 강화에 따라 상위 티어 확률이 증가합니다. 10회 소환은 총 비용을 표시하고, 공간·재화 부족 시 결제하지 않습니다. 재료 3종으로 신화를 확정 조합할 수도 있습니다.
- 세파계·카바페넴·세포벽·단백질 억제·항바이러스·세포막 / 그람 양성·음성·바이러스·진균·협막 특성. 서로 다른 기물 수에 따라 전장 전체에 게임용 보너스가 적용됩니다. 공격력·행운 강화와 보스 후 3택1 증강을 제공합니다. 27종 기물마다 연사·관통·유도탄·연쇄 전격·속박·독 장판 등의 고유 공격과 사거리를 갖습니다.
- 적 60마리 누적 또는 보스 제한 시간 초과 시 패배. 20웨이브 전멸 시 승리. 배속, 음소거, 일시정지, 진영별 최고 기록과 같은 시드 재도전.
- 모바일 탭 조작. 데스크톱 Q 소환 / W 10회 소환 / E 행운 / Space 일시정지. 탭 이탈·창 비활성 시 자동 정지. 새로고침하면 진행 중인 전투는 초기화됩니다.
- 화면 높이에 맞춘 전장, 모바일 특성·강화·조합 패널, 페이지 방식 도감. 기물은 작은 크기로 제자리 움직임을 표시하며, 일시정지와 동작 줄이기 설정을 따릅니다.
- 기존 투명 그림·MIT Kontra.js·[Lucide 0.468.0](https://lucide.dev) SVG 아이콘(ISC)·합성 Web Audio 재사용. 진입할 때 모듈을 불러오고, 방문 후 오프라인 캐시를 사용합니다.

## survival — 탑다운 자동 공격 생존

상단 **survival** 또는 `#survival`에서 실행합니다. 5분 생존과 **군집의 심장** 제거를 모두 달성하면 격리 성공입니다. 보스가 남으면 5분 이후에도 목표를 표시하며 전투를 이어갑니다.

- WASD / 방향키 / 전장 드래그로 이동, P / Esc 일시정지, 1–3 강화 선택. 보스를 클릭·탭하면 10초 동안 자동 공격의 우선 표적이 됩니다.
- 가까운 검체 동선으로 성장 시작. 강화는 카드 3개만 표시하며 실제 피해·발사 수·관통·범위·간격의 전후 수치를 비교합니다. 연속 선택 사이 0.48초 확인, 재개 후 1.2초 피격 보호.
- 무기 4종은 Lv.3부터 각각 2개 진화 중 하나를 선택합니다. 다중/관통 펄스, 밀착/외곽 위성, 연속/중력 파동, 그물/집중 방전. 패시브와 최종 수치는 장비 탭에서 확인합니다.
- 돌진·원거리·구역 차단·분열 군집, 약한 적 간격 유지, 방향성 유입·집중 교전·회수·재정비. 보스는 90/180/270초에 출현하며 돌진·고리·부채꼴·소환을 구분해 예고합니다.
- NOVA는 보이는 충격파가 닿을 때 피해·밀쳐내기를 적용합니다. ARC는 순차 연결, 무기별 효과음은 묶음 처리하며 동시 8음으로 제한합니다.
- 모바일 시야와 화면 밖 안전 생성, 경계 카메라, 위협 방향 표시. 보급 단말·8초 안전지대·위험 검체 저장소로 이동 목적을 제공합니다.
- 성공 횟수·최단 완료·최고 처치·실패 시 생존을 분리해 저장합니다. 최근 12회 빌드·강화 순서·시드로 재도전합니다. 탭 이탈·창 비활성 시 자동 정지하며 새로고침은 현재 전투를 초기화합니다.
- 관찰 탭에서 형태 모티브를 보고 병원체 도감을 선택해서 열 수 있습니다. 전투는 가상 장비·군집 성장 중심이며 항생제 coverage를 적용하지 않습니다.
- 진입 시 모듈을 불러오고 최초 방문 후 오프라인 캐시를 사용합니다. 추가 런타임 의존성은 없습니다.

설계·검증 범위는 [Survival 피드백 반영](docs/survival-design.md), 전략 비교 원자료는 [밸런스 측정](docs/survival-balance.json)에 있습니다.

## shoot — Isolation Protocol

상단 **shoot**에서 경량 2.5D 감염 FPS를 실행합니다. 기존 Kontra.js(MIT)·Canvas 레이캐스팅을 재사용하며 새 런타임 패키지는 없습니다. shoot 코드와 스타일은 진입 시에만, CC0 음악 5곡은 MUSIC ON일 때 선택한 곡만 불러옵니다.

- **전투와 시야:** 일반 적 크기 약 24%, 추격 속도 22% 감소. WASD, 상하좌우 마우스 조준, Space 점프, Shift 대시. 일반 구역은 같은 방·근거리·시야·벽 가림 조건으로만 어그로가 시작합니다. 직접 맞힌 적은 반응하고, 시야를 놓치면 마지막 위치를 수색합니다.
- **슬롯과 스캔:** 중앙 하단 9칸 약제, 왼쪽 별도 보조 스캐너. 우클릭 유지로 2× 검사, 놓으면 원래 약제로 복귀. 학습은 검사한 개체의 유효 약제에 금색 테두리, 일반은 이름·AST, 동정은 이름만 공개, 실전은 형태 → 배양 → AST 순으로 해금합니다.
- **캠페인:** 8개 감염 구역, 6개 구역의 진행형 시설, 시드별 치수·접근로, 실제 계단과 관측 데크, 중간보스 후 열리는 지름길. 총 144개체와 구역별 중간보스·MSSA/Pseudomonas/KPC 스테이지 보스를 모두 소탕하고 출구에서 탈출합니다. 잔여 3개체부터 위치 펄스와 경로를 안내합니다. 후반에도 최소 약 30%의 일반형을 유지합니다.
- **무한 생존:** ENDLESS는 혼합 임상 사례 아레나입니다. 유입·집중 교전·정리·재정비 흐름, 2분 주기 중간보스/보스, 검체 경험치, 레벨마다 3택1 증강, CRO 자동 위성·격리 잔상·면역 연계 공격·수집 드론·회복·소독 장비 조합. 90초 후 출구에서 철수하거나 계속 생존할 수 있습니다. 특수 병원체는 후기부터 등장하며 필요한 약제가 먼저 보급됩니다.
- **재장전과 소모품:** R 재장전은 이전보다 20% 빨라졌고 탄창 분리·삽입·장전 소리가 납니다. G로 소독탄을 던져 4.5초 범위 소독장을 만듭니다. 휴면 포자·기생충과 벽 뒤 표적에는 효과가 없습니다. 시작 3개, 최대 5개, 보급으로 회복합니다.
- **임상 복습:** 구역 결과에서 병원체 이미지·처치·유효/무효·첫 유효 선택·오답 후 전환·더 좁은 유효 약제 사용 기회를 확인합니다. 상황별 우선 치료와 근거는 공통 도감 DB에서 가져오며, 현재 감염부위와 다르면 별도 임상 사례로 표시합니다. 감수성 판정과 임상 우선순위를 혼동하지 않습니다.
- **화면과 소리:** 가용 화면을 채우는 자동 비율·전체화면, 작은 퀵슬롯과 빨간 체력바, 우하단 원근 총기. Freedoom 소형 텍스처·의료 보급함, 문틀·조명·구역 표식·검체 선반. PNG 7개는 shoot에서만 지연 로드. CC0 음악 5곡의 자동 선곡·직접 선택·다음 곡·ON/OFF. 전체 미니맵 / 시야 탐색 공개 선택, M으로 펼치기.
- **공통 데이터:** 도감의 17개 고정 분리주/임상형과 12개 약제. 수동·자동 약제 공격과 지속 노출 모두 같은 coverage 판정을 통과하며 R은 업그레이드로 바뀌지 않습니다. F는 biofilm·휴면 포자·오염 구역 제거, Esc는 일시정지, B는 도감입니다.
- **테마 작전**: 바이러스 연구동(HSV·CMV) / 기생충 온실(Giardia·Strongyloides), 필요한 약제를 즉시 보급합니다.
- **면역 동료**: 호중구·대식세포·NK세포·호산구 중 1개 장착, 맵 지원 상자·보상·증강으로 획득합니다.
- **무기 손맛:** 연사·산탄·충전·점사·관통·지속 빔·펄스와 서로 다른 반동·효과음. 관통과 다중 타격도 적마다 AST를 따릅니다.
- **메뉴와 HUD:** 작전·난이도 / 환경·조작 / 고급 3탭, 획득 동료는 장비에 통합. 전투 중 현재 약제·탄약·HP·선택압을 중심으로 표시합니다. 터치 감도·조준 보정·슬롯 스와이프를 제공합니다.

구조·임상 판정·한계는 [shoot 문서](docs/play-prototype.md)에 정리했습니다. 맵과 적은 임상 요소의 게임 표현이며 실제 처방·용량·임상 효과를 뜻하지 않습니다.

## 게임

- **182종·균군, 209개 병원체/표현형 기록, 80개 약제, 4,733개 패널 내 약제 단서.** 세균 86 / 진균 23 / 바이러스 42 / 기생충 31종·군.
- 세균 감수성 / 세균 치료 단서 / 진균 / 바이러스 / 기생충의 5개 출제 분야. 각 분야의 후보군과 고정 약제 목록을 사용합니다. [전체 수록 목록](docs/data-coverage-v0.7.0.md).
- 약제 검색·16개씩 페이지 전환, Archive 내 약제 도감(기전·활성 범위·제한점·내성).
- 모바일 하단 정보/약제/정답 전환과 44px 이상 터치 영역.
- 숨은 답은 독립 ID를 가진 교육용 분리주 또는 지침 기반 임상형입니다. 무작위 AST나 MIC를 생성하지 않습니다.
- 같은 관찰 결과를 갖는 후보로 조건화한 Shannon entropy H를 계산합니다.
- 검사 비용: `ceil(6 + 18 * H)`; 모든 결과가 같으면 최소 6.
- 공개 전의 **기대 정보량**으로 가격을 정하므로 숨은 답에 따른 가격 누설이 없습니다.
- 결과 비교는 플레이어가 보는 힌트 본문 전체 또는 약제 결과 범주를 기준으로 합니다. 병원체별 상세 조건·출처는 동정 후 공개합니다. 개별 공개 비용은 버튼에 표시하지 않습니다.
- 점수: `max(0, 1000 - 4 * totalCost - 100 * distinctWrongGuesses)`.
- 같은 힌트/약제를 다시 공개하거나 같은 오답을 반복하면 추가 비용이 없습니다.
- 병원체와 표현형·임상형이 모두 일치해야 정답입니다. 임상형이 하나면 자동 선택됩니다.
- **답 보기**로 정답과 전체 정보를 공개할 수 있습니다. 이 라운드는 Archive·최고점·동정 횟수에 반영하지 않으며, 새로고침하거나 분야를 바꿔도 공개 상태가 유지됩니다.
- 미완료 검체 교체는 Archive에 등록하지 않습니다. 정답은 최고점과 동정 횟수를 누적합니다.
- 분야별 라운드·정답 선택과 Archive는 localStorage에 저장됩니다. 오답 시점까지 기록해 새로고침 후 비용을 다시 검증합니다. 서버·계정·기기 간 동기화는 없습니다.
- 정적 학습 게임이므로 개발자 도구로 데이터와 정답을 볼 수 있습니다. 경쟁형 anti-cheat를 제공하지 않습니다.

## 도감과 발견 기록

전체 카드 열람은 **카드 도감**으로 통합했습니다. 약제 계열·감염질환 분류·발견 기록은 아래 검색창 옆의 필터에서 고릅니다. 기존 `#library`, `#drugs`, `#archive`는 각각 병원체·약제·발견 기록으로 연결되며 `#cards/diseases`에서 감염질환을 바로 엽니다. 도감 열람은 게임 라운드·점수·Archive를 변경하지 않습니다.
발견 기록에서는 기존 저장 기록의 최고점·동정 횟수와 전체 병원체 기록 대비 진행률을 표시합니다. 검색·분류·내성형 겹쳐 보기는 발견한 카드 범위 안에서 적용됩니다.

## 카드와 재사용 도감 DB

병원체 182종·감염질환 259종·약제 80종에 투명 배경 삽화 521장을 연결했습니다. 내성형·표현형 카드는 기본 병원체의 그림을 공유합니다. 검색창 위의 작은 **그림 보기** 체크박스로 그림을 숨기거나 표시하며, 선택은 다음 방문에도 유지됩니다. 카드 크기·설명·좌우 기호와 뒤집기 동작은 그대로 유지합니다. 그림은 무손실 WebP로 배포하고, 열어본 카드부터 불러와 저장합니다. 개별 프롬프트·수정 이력과 원본 보존 방식은 [병원체·질환 그림 작업 기록](assets/cards/production-v1/README.md)과 [약제 그림 작업 기록](assets/cards/drug-production-v1/README.md)으로 관리합니다. 항기생충제 19종은 원충·연충·외부기생충에 따라 파리채·잠자리채·집게로 구분하며, 세부 문양은 [개정 기준](assets/cards/parasite-production-v2/README.md)을 따릅니다.

상단 **카드 도감** 또는 `#cards`를 열면 먼저 **병원체·항생제·질병 세 덱 뭉치**가 나옵니다. 덱을 누르면 해당 카드 목록이 열리고 작은 **← 덱** 버튼으로 세 뭉치 화면에 돌아갑니다. 첫 화면의 검색은 전체 카드, 덱 안의 검색은 해당 분류에 적용됩니다. 세 덱에 수록된 **병원체·표현형 209장, 약제 80장, 감염질환 259장으로 총 548장**을 같은 임시 디자인으로 열람합니다. 전체·병원체·세균·진균·바이러스·기생충·약제·감염질환 분류, 이름·표현형·계열·핵심 요약 검색, 내성 표시 필터와 약제 계열 필터를 제공합니다. 카드 도감은 24장씩 작은 카드로 모아 보여주며, 모바일은 2열이고 데스크톱은 기본 폭 약 190px의 다열 격자입니다. 덱 안의 목록은 상단 소개·설명 없이 카드 격자부터 시작하며, 중앙 아래 검색창 옆의 필터 버튼으로 분류·겹쳐 보기와 160/190/220px 목록 밀도 설정을 엽니다. 병원체 한글명·관용명과 약제 80개의 한글 이름을 영문 이름과 함께 검색하며, 띄어쓰기·하이픈·대소문자 차이를 무시합니다. 카드를 누르면 하나를 확대하고 현재 페이지의 이전·다음 카드를 넘깁니다.

앞면은 **대표 임상상·환자/노출 맥락·치료 선택을 바꾸는 특징**을 담은 한두 문장, **뒷장**은 상세 생물학·진단·질환·내성·약제 반응·적용 조건을 담습니다. 앞뒤가 같은 2:3 크기이며 3D 회전으로 뒤집습니다. 확대 카드의 뒷면은 임상 / 약제·대상 / 기호 탭으로 나누고 각 내용만 내부에서 스크롤합니다. 마우스 위치에 따라 약간 기울어지고, 모바일에서는 카드 표면을 좌우로 쓸어 뒤집거나 아래 버튼을 누릅니다. 모션 감소 설정에서는 움직임을 줄입니다. MRSA·VRE 등 이름이 붙은 내성은 공통 카드의 우상단 대각선 띠로 표시합니다. 분야별 색상과 SVG 기호는 재사용하며, 중앙에는 각 카드에 연결된 투명 배경 삽화를 표시합니다. 약제 경로는 기존 기록에 명시된 값만 사용하고 미지정은 `—`로 표시합니다.

| 영역 | 기본 360×540px 기준 |
| --- | --- |
| 전체 | 2:3 비율, 작은 화면에서는 비례 축소 |
| 이름 | 위쪽 변 중앙 |
| 경로 | 좌상단 약 40px 배지 |
| 그림 | 상·중단 약 296×296px 사각 창 |
| 계통 | 그림/텍스트 경계 약 29px 띠 |
| 핵심 요약 | 중·하단 약 144px, 한두 문장 |
| 기호 | 양쪽 세로 레일, 기호 약 14px |
| 내성 | 우상단 대각선 띠 |
| 뒷장 | 동일 비율 안에 상세 설명·연결, 내용 영역 스크롤 |

병원체의 왼쪽은 부위별 질환이 정리된 장기, 오른쪽은 해당 기록에 효과 있는 약제입니다. 장기 호버에는 그 부위의 질환명, 약제 호버에는 영어 약제명과 필요한 판정·조건을 표시합니다. 설명창은 카드 기울기 밖에 하나만 표시하며, 근거 목록·수록 기록 개수는 호버와 카드 뒷면에서 표시하지 않습니다. 약제의 왼쪽은 활성·요법 포함 기록이 있는 병원체 계통, 오른쪽은 R·비활성이 명시된 계통입니다. 계통 내 표현형별 판정이 다르면 양쪽 모두 켜질 수 있으며 세부 기록은 기호 설명과 뒷장에 나옵니다. `OUTSIDE_REGIMEN`은 무효로 집계하지 않습니다. 장기는 폐·신경계·혈류·심장/판막·피부·소화기·요로·간/담도·뼈/관절·눈 기호로, 약제는 약통/캡슐·주사기와 짧은 약제 약어로 구분합니다. 약제 카드의 병원체군은 포도알균·사슬알균·장알균·장내세균목·비발효균·기타 세균·진균·바이러스·기생충의 9개 고정 슬롯입니다. `src/card-models.mjs`가 DB를 카드 속성에 연결하고 `src/card-gallery-ui.mjs`가 목록을 제공합니다. `src/card-inspector.mjs`가 카드만 드러나는 확대 화면과 작은 뒤집기·내성형 선택·이전/다음 버튼을 담당합니다. `src/reference-card.mjs`와 `src/reference-card.css`가 공통 틀이며 `summary`와 `back`을 주입합니다. 그림은 `artwork: { src, alt }`, 장식 프레임은 `--card-frame-image`로 교체합니다.

검색창 오른쪽의 동그란 **i** 버튼은 병원체·항생제·질병 안내를 엽니다. MRSA·Oxacillin·지역사회획득폐렴을 실제 카드 틀에 표시하고, 이름·경로·그림·분류·요약·좌우 기호·내성 테이프에 번호를 붙였습니다. 번호를 누르면 같은 크기의 뒷면에서 해당 설명으로 이동합니다. 데스크톱에서는 세 예시를 함께, 모바일에서는 종류 선택 버튼으로 하나씩 봅니다. 안내는 도감 검색·필터·진행 기록을 바꾸지 않습니다.

### 감염질환 카드

259개 질환을 호흡기·귀코목·혈류/심장·중추신경·장/복강·간담도·요로·산과/생식기·피부·뼈관절·눈·성매개·전신 세균·바이러스·진균·기생충의 16개 분류로 수록합니다. 감염이 중심 기전인 질환과 감염성 임상 증후군을 포함하고, 감염 후 면역질환·병원체 연관 종양·단순 집락화·비감염성 염증은 제외합니다. 임상형에 따라 관리가 달라지는 활동성/잠복결핵·칸디다 점막/혈류감염 등은 구분했습니다. [전체 질환 목록과 작성 규칙](docs/infectious-disease-cards.md).

앞면에는 임상 단서 한두 문장, 뒷면 임상 탭에는 특징·진단·치료/관리·주의할 상황이 있습니다. 좌측 작은 기호는 원인 병원체군, 우측은 치료 약제 또는 대증치료입니다. 대증·지지치료가 중심인 질환은 `supportiveCare`로 명시하고 흰색 의료 십자와 앞·뒷면의 ‘대증치료’ 문구를 표시합니다. 뒷면 **연결** 탭에서 원인 병원체·약제·관련 질환 카드를 열 수 있고 왼쪽 화살표로 원래 카드의 뒷면에 돌아옵니다.

치료 상황을 선택하면 해당 요법의 구성 약제가 금색(우선) 또는 흰색(대안/조건부)으로 켜집니다. 다른 상황의 약제는 회색이며, 단독·병합·순차와 전체 요법/구성 성분을 구분합니다. 보조 약제는 우선 항균제로 금색 표시하지 않습니다. 기존 DB에 없는 약제·병원체는 영문 이름으로 남기고 잘못된 카드 ID를 만들지 않습니다. 출처·근거 수·기록 수는 앞뒤·호버에 표시하지 않습니다.

### 편집 원본과 생성 데이터

요약은 분류·구조·작용점 나열보다 임상 특징을 먼저 씁니다. 병원체는 대표 감염·숙주·노출·합병증, 약제는 주된 사용처와 중요한 사용 한계, 내성 변형은 같은 감염에서 달라지는 약제 선택을 담습니다. 생물학·작용기전의 상세 설명은 뒷장의 기존 섹션에 둡니다.

**182종·군의 기본 요약, 209개 표현형·임상형의 앞면 요약, 80개 약제 요약**을 채웠습니다. 다중 표현형 41개는 개별 요약을 직접 작성하며, 단일 기록은 병원체 공통 요약을 사용합니다. 이름이 붙은 내성은 별도 `resistance: { code, label }`로 저장합니다.

| 파일 | 편집 내용 |
| --- | --- |
| `content/cards/bacteria.json` | 86종·군 세균 요약 |
| `content/cards/fungi.json` | 23종·군 진균 요약 |

`npm run seed:cards`가 편집 원본과 현재 `data/organisms.json`을 합쳐 **`data/library.json`**을 생성합니다. 전체 `npm run seed`와 빌드에도 생성 단계가 연결됩니다. 생성 JSON을 직접 고치지 말고 요약은 `content/cards/`, 의료 사실은 기존 seed·확장 원본을 편집하세요. 새 ID를 추가하면 요약 원본도 추가해야 생성할 수 있습니다.

`data/library.json`은 ID를 키로 쓰는 정규화된 JSON DB입니다. 파일명은 재사용 데이터 계약으로 유지하며 화면의 라이브러리 메뉴와는 독립적입니다.

`npm run validate:cards`로 ID·분류·반응·출처·치료/질환의 양방향 참조와 상세 상속·집계·데이터 버전 일치 여부를 검사합니다. 같은 검사가 생성 및 빌드에도 연결되어 잘못된 DB가 저장되는 것을 막습니다. 출제 분야에 상세 항목을 추가하면 도감 뒷면도 해당 목록에서 함께 생성합니다.

- `pathogens[taxonId]`: 병원체 공통 이름·분류·요약·상세 섹션.
- `variants[recordId]`: 공통 병원체 참조 `pathogenId`, 표현형·임상형 요약, 내성 표시와 상세 차이.
- `drugs[drugId]`: 약제 이름·계열·요약·상세 섹션.
- `diseases[diseaseId]`: 질환 이름·검색명·임상 요약·상세·원인 병원체·치료 상황·관련 질환. 병원체·약제의 `diseaseIds` 역참조를 같은 원본에서 생성.
- `diseaseCategories`, `diseaseRoutes`, `diseaseEntityTypes`: 질환 분류·경로·종류의 재사용 코드표.
- `responses[recordId][drugId]`: 실제 약제 반응의 profile ID.
- `responseProfiles[profileId]`: 중복 없이 보관한 판정·기전·적용 조건·출처. ID는 내용에서 생성되므로 목록 순서에 의존하지 않습니다. 원본 반응의 출처 배열은 반복 인용까지 보존해 기존 ID를 유지하며, 카드의 통합 근거 목록에서만 중복을 제거합니다.
- `sources`, `panels`, `categories`, `interpretation`: 근거와 관찰 범위·판정 의미를 함께 제공.

`src/card-catalog.mjs`의 `createCardCatalog(db).pathogen(recordId)`· `.drug(drugId)` · `.disease(diseaseId)`가 앞면 요약과 뒷면 내용을 반환합니다. 변형의 상세 섹션은 같은 ID의 공통 섹션을 덮어쓰고, 나머지는 상속합니다. 게임용 `organisms.json`은 호환용 출력으로 유지되며 도감 정보는 별도 DB로 재사용합니다. 기존의 S/I/R·조건부 활성·문헌상 활성·요법 포함 여부와 적용 조건을 그대로 구분합니다.

## defense — 항생제 전선

상단 **defense** 또는 `#defense`에서 실행합니다. 스테이지의 적 조합·AST를 먼저 보고 **4슬롯 / 10P 항생제 덱**을 편성한 뒤, 횡방향 전장에 약제 유닛을 출격시킵니다.

- 폐·요로·복강의 12개 스테이지. 일반 감수성균 → MRSA / ESBL / Pseudomonas / KPC / VISA / LZD 내성 MRSA로 대응 조합이 바뀝니다. 이전 스테이지 클리어로 다음 작전을 개방합니다.
- 모든 약제는 처음부터 편성 가능하며 전투 중 덱은 고정됩니다. I 대응 노출 설정은 편성 비용 +1P·출격 비용 +20%. 신기능 조정과 알레르기, 감염 부위 조건을 확인해야 출전할 수 있습니다.
- 자동 자원 수입, 출격 쿨다운, 보급·유효 약제의 투여 효율 강화. 증원과 동일 AST를 가진 잔존 군집을 제거하면 승리합니다. 농양은 별도의 source control을 병행합니다.
- 적 구성과 AST는 항상 공개됩니다. 유입시간 분석은 시작 자원 45를 써서 다음 증원의 균종·도착 시간까지 표시합니다. 선택압은 출격 비용에, microbiome 교란은 스테이지별 평가에 반영합니다. 임의의 내성 변환이나 숨겨진 적은 없습니다.
- 약제·분리주·해설·출처·부위 제한은 기존 `data/organisms.json`을 직접 참조합니다. R·비활성 약제는 공격하거나 적을 몸으로 막지 못합니다. 조합제는 원본 판정만 사용하며, REGIMEN·OUTSIDE_REGIMEN·문헌 활성은 S/R로 바꾸지 않습니다. CZA의 KPC 판정을 모든 CRE에 일반화하지 않습니다.
- 1–4 출격, Space 정지, 1/2배속·효과음·음악·전체 화면. 한 화면에서 편성과 전투를 진행하며 상세 자료는 팝업으로 확인합니다. 덱·노출 설정·스테이지별 별 기록을 저장하고 패배 후 같은 덱을 고쳐 재도전합니다. 새로고침 시 진행 중인 전투는 초기화됩니다.

전용 검사 8개에서 임상 판정 보존·편성 제한·덱 고정·무효 약제의 통과·지원 액션을 확인하며, 각 스테이지를 대응 덱과 일반 조작으로 한 차례씩 완주합니다. 모든 선택의 승리를 보장하는 검사는 아닙니다. 전투 수치는 실제 용량·MIC·임상 효과 크기가 아닙니다.

형식은 [PONOS의 The Battle Cats](https://www.ponos.jp/en/games/thebattlecats/)와 [공식 유닛 가이드](https://ponosgames.com/information/appli/battlecats/zukan/en/index.html)의 조합·출격 구조를 참고했습니다. 그래픽은 자체 Canvas 드로잉이며 기존 게임 에셋을 복제하지 않습니다. Phaser·Kenney 공개 에셋도 검토했고, 기존 **[Kontra.js 10.0.2](https://github.com/straker/kontra) (MIT)**의 GameLoop / Pool과 이미 포함된 **[Chiptune Battle — pmiller](https://opengameart.org/content/chiptune-battle-music) (CC0)** 음원을 재사용합니다. 라이선스는 `src/vendor/KONTRA-LICENSE.txt`, `src/play-assets/LICENSE.txt`에 있습니다.

## 의료 데이터의 의미

`data/organisms.json`이 플레이 데이터, `data/schema.json`이 확장용 JSON Schema,
`data/sources.json`이 근거 목록입니다. 핵심 seed, `scripts/sources.base.json`, `scripts/expansion/*.json`이 작성 원본이며 `npm run seed`로 병합합니다.
수동 JSON 수정은 seed 재생성 시 덮어써지므로 seed와 확장 패키지를 작성 원본으로 유지하세요. `npm run build`도 전체 조합·출처 검증을 수행합니다.

원본 `19 the medicine resource`는 **읽기 전용**으로 참고했습니다. 개인정보·학습 이력·원문 전체는 배포하지 않습니다.
`docs/source-audit.json`에는 참고한 파일의 상대 경로와 SHA-256을 기록합니다.
기존 spectrum의 `variable/conditional`을 S로 자동 매핑하지 않았습니다.

현재 검증의 한계와 미해결 문제는 [데이터 감사 기록](docs/data-audit-2026-09-30.md)에 정리했습니다. 출처 링크와 자동 테스트 통과가 모든 조합의 의학적 검증을 뜻하지 않습니다.

전체 데이터의 검토 상태는 **educational-draft**입니다. 세균 감수성 분야는 문헌 제약을 반영한 고정 교육용 분리주이고, 나머지 분야는 **명시된 감염·병기·숙주 조건에서 문헌 요법에 포함되는 약제**를 단서로 삼습니다. 구조·게임 테스트가 전문 임상 검토를 대신하지 않습니다.

`REGIMEN`은 표준·대안 요법의 구성 약제(병용·투여경로·선행검사 조건 포함), `OUTSIDE_REGIMEN`은 이 기록이 인용한 요법 목록에 없다는 뜻입니다. 후자는 비활성·내성·금기를 뜻하지 않습니다. 지지요법이 중심인 바이러스도 이 구분을 사용합니다. 게임 JSON은 호환성을 위해 약제 단서를 `susceptibility`에 저장하되 `observationType`, `basis`, `clinicalContext`로 의미를 명시합니다.
S/I/R의 의미 및 일부 조합의 추론 규칙은 EUCAST v16.1 (2026)을 따릅니다.
`I = Susceptible, increased exposure`; R 또는 CLSI Intermediate와 같지 않습니다.
배포 검증은 NA·빈 값·일반적인 “추가 AST 필요” 자리표시자를 차단합니다. S/I/R 근거가 없는 조합은 임의 판정 대신 적용 조건과 확인된 활성을 작성합니다. ACT는 고노출·병용·상승작용 등 명시된 조건에서의 활성입니다. ACTIVE/INACTIVE는 문헌 기반 항균 활성로 임상 S/I/R 범주와 구분합니다. Breakpoint 부재를 비활성으로 간주하지 않습니다. E. coli cefazolin은 요로 유래 감염 범위입니다.
개별 실제 균주를 대변하거나 임상 처방을 권고하는 데이터가 아닙니다.

MSSA/MRSA, MSSE/MRSE, E. faecalis/faecium VSE/vanA VRE, E. coli baseline/ESBL,
K. pneumoniae ESBL/KPC, P. aeruginosa non-DTR/DTR, E. cloacae inducible/derepressed AmpC를 포함합니다.
Glycopeptide 감수성, ESBL 이후의 비-β-lactam 결과 등은 해당 분리주의 설정이며 종/phenotype 전체의 보편적 결과가 아닙니다.

MIC와 breakpoint는 현재 모두 null입니다. 고급 모드는 의도적으로 비활성화했습니다.
활성화 전에는 약제·균종·감염부위·노출조건·표준·버전을 고정하고
실측/교육용 MIC 출처 및 수치 판정 테스트를 추가해야 합니다. ECOFF는 임상 breakpoint 대신 쓰지 않습니다.

새 데이터를 추가할 때:

1. 새 taxon/phenotype 조합에 고유 ID를 부여합니다. 기존 기록의 ID는 재사용하지 않습니다.
2. 해당 패널의 모든 힌트와 약제 조합을 전문 출처로 채웁니다. NA·빈 값은 금지합니다. S/I/R, 예상 내성, 조건부 활성의 근거를 구분하고 부위·노출·병용 제한과 해당 출처를 명시합니다. 근거를 확보하지 못한 조합은 데이터에 추가하지 않습니다.
3. 패널·분야·관찰 유형, 출처, 검토 상태, 해석 규칙을 입력합니다. 요법 단서는 명확한 clinicalContext와 해당 상황의 표준·대안요법 근거를 요구합니다. 종의 특성과 분리주의 내성을 분리합니다.
4. 동일한 힌트는 본문을 동일하게 유지합니다. 관찰 본문이 바뀌면 정보량 계산도 바뀝니다.
5. 데이터 버전을 올리고 seed와 테스트를 실행합니다. 데이터 버전 변경 시 진행 중 라운드는 초기화되며 유효한 Archive ID는 유지합니다.
6. 전문가 검토 후에만 reviewStatus를 expert-reviewed로 변경합니다.

## 항생제 선택 모드

상단 **항생제 선택** 또는 `#treatment`에서 플레이합니다. 성인 임상 사례 32문항: 증상 → 경험적 항생제 10, 병원체 → 표적 항생제 12, 질병 → 치료 요법 10. 전체 혼합/트랙별 무작위 최대 10문항 세트를 제공합니다. 문항 및 선택지 순서를 섞으며 같은 세트에서 문항을 반복하지 않습니다.

- 감염 부위·중증도·숙주·감수성·내성 기전·약제 가용성을 명시하고, 제시된 선택지/지침 조건에서 답을 고릅니다. 병원체 추측의 S/I/R 타일에서 치료 정답을 자동 추론하지 않습니다.
- 제출 후 변경 없이 채점하고 정답 이유, 선택지별 해석, 요법·투여 조건, 인정되는 대안, 재평가·치료 축소, 핵심 판단과 출처를 공개합니다.
- 답을 직접 확인한 문항은 정답률에서 제외하고 복습 목록에 남깁니다. 오답 또는 답 확인 후 나중에 직접 맞히면 복습 목록에서 빠집니다.
- 트랙/범위별 세트와 오답 기록을 `pathopedia.treatment.v1`에 별도 저장합니다. 새로고침·병원체 추측 이동 후 이어 풀 수 있습니다. 병원체 추측 Archive와 점수는 기존 저장 키를 사용합니다.
- 근거 21개 문서의 기관·출판/지침 연도·지역·관련 절·확인일을 기록합니다. IDSA 2026 AMR, 2025 cUTI, WHO 2025 수막염, ESC 2023, CDC STI, SHEA/IDSA CDI 및 국내 요로감염 지침 등을 사용합니다. 오래된 지침의 지역 내성률을 현재 수치로 간주하지 않습니다.
- 전체 문항은 **교육용 초안 / 전문 임상 검토 전**입니다. 문헌 확인과 구조·게임 테스트가 임상 전문가 검토를 대신하지 않습니다. 해외 신약의 국내 허가·공급 및 모든 실제 환자의 투여 조건을 보장하지 않습니다.

작성 원본은 `scripts/seed-treatment.mjs`, 플레이 데이터는 `data/treatment-questions.json`입니다. `npm run seed:treatment`로 재생성하고 `npm run validate:treatment`로 필수 임상 조건·선택지·해설·근거 참조를 검사합니다. `npm run seed`도 두 데이터 세트를 함께 재생성합니다. 문항 변경 시 치료 datasetVersion을 올려 이전 답/선택지에 의한 오채점을 방지합니다.


금색은 특정 임상 상황에서 근거가 연결된 우선요법, 흰색은 그 외 유효·요법 포함 기록, 약제 오른쪽의 붉은색은 R·비활성, 회색은 비해당·기록 없음입니다. 병용·증가 노출·판정 혼재 조건은 작은 파란 점으로 덧붙입니다. 우선요법은 `S` 결과에서 추정하지 않습니다.

`content/cards/therapies.json`에 43개 임상 상황의 `recordIds, context, drugIds, excludedDrugIds, sourceIds, note, combination` 및 선택적인 `sites, scenarios, learningDefault, preferenceLabel, requiresCompanion`을 분리해 작성했고 생성 DB의 `therapyContexts` 및 기록별 `therapyIds`로 연결합니다. 확대 화면의 금색은 병원체 카드의 기본 임상 상황 또는 약제 카드의 수록 임상형 전체를 기준으로 하며, 해당 상황·조건은 카드 뒷면과 기호 설명에서 읽습니다. 약제 카드의 전체 보기에서 금색은 그 계통에 우선요법 대상 임상형이 있다는 뜻이며 모든 종·표현형·감염 부위의 일차약이라는 뜻은 아닙니다. 미지정 우선순위는 알 수 없음이며 흰색을 곧 2차 약제로 읽지 않습니다.

내성형 겹쳐 보기는 같은 병원체 ID의 기본형과 내성형을 한 목록으로 묶습니다. 묶음마다 펼치기/접기를 지원하며, 전체 스위치를 끄면 모든 카드를 개별로 표시합니다. 검색·분류·발견 기록에서 제외된 카드는 묶음에 포함하지 않고, 확대 창의 작은 내성형 버튼을 눌렀을 때만 기본형·내성형 선택지가 나옵니다. 보기 설정은 로컬에 보관합니다.

데스크톱에서는 화면 높이에 맞춘 고정 보드이며, 작은 모바일 화면/높은 확대 배율에서는
글자를 과도하게 줄이지 않도록 세로 스크롤 배치를 사용합니다.
