# PATHOPEDIA

병원체 동정과 가이드라인 기반 항생제 선택을 복습하는 의사·의대생용 웹게임.
세균·진균·바이러스·기생충의 연구 기록과 발견 Archive를 제공합니다.
상단 메뉴는 **동정실 · 항생제 선택 · 라이브러리 · 카드 도감**의 네 탭입니다.

## 실행

Node.js 20 이상. 런타임 의존성이 없는 정적 ES module 앱입니다.

```sh
npm ci
npm run dev
npm test
npm run build
```

개발 서버: http://127.0.0.1:4173. 빌드 결과: `dist/`.
GitHub Actions가 main push 시 테스트 → 정적 빌드 → Pages 배포합니다.
저장소 Pages의 source는 GitHub Actions입니다. `/pathopedia/` 하위 경로에 호환됩니다.

## 게임

- **182종·균군, 209개 병원체/표현형 기록, 80개 약제, 4,733개 패널 내 약제 단서.** 세균 86 / 진균 23 / 바이러스 42 / 기생충 31종·군.
- 세균 감수성 / 세균 치료 단서 / 진균 / 바이러스 / 기생충의 5개 출제 분야. 각 분야의 후보군과 고정 약제 목록을 사용합니다. [전체 수록 목록](docs/data-coverage-v0.7.0.md).
- 약제 검색·16개씩 페이지 전환, Archive 내 약제 도감(기전·활성 범위·제한점·내성).
- 모바일 하단 정보/약제/정답 전환과 44px 이상 터치 영역.
- 숨은 답은 독립 ID를 가진 교육용 분리주 또는 지침 기반 임상형입니다. 무작위 AST나 MIC를 생성하지 않습니다.
- 같은 관찰 결과를 갖는 후보로 조건화한 Shannon entropy H를 계산합니다.
- 검사 비용: `ceil(6 + 18 * H)`; 모든 결과가 같으면 최소 6.
- 공개 전의 **기대 정보량**으로 가격을 정하므로 숨은 답에 따른 가격 누설이 없습니다.
- 결과 비교는 플레이어가 보는 힌트 본문 전체 또는 약제 결과 범주를 기준으로 합니다. 병원체별 상세 조건·출처는 동정 후 공개합니다. 개별 공개 비용은 버튼에 표시하지 않습니다.
- 점수: `max(0, 1000 - 4 * totalCost - 100 * distinctWrongGuesses)`.
- 같은 힌트/약제를 다시 공개하거나 같은 오답을 반복하면 추가 비용이 없습니다.
- 병원체와 표현형·임상형이 모두 일치해야 정답입니다. 임상형이 하나면 자동 선택됩니다.
- **답 보기**로 정답과 전체 정보를 공개할 수 있습니다. 이 라운드는 Archive·최고점·동정 횟수에 반영하지 않으며, 새로고침하거나 분야를 바꿔도 공개 상태가 유지됩니다.
- 미완료 검체 교체는 Archive에 등록하지 않습니다. 정답은 최고점과 동정 횟수를 누적합니다.
- 분야별 라운드·정답 선택과 Archive는 localStorage에 저장됩니다. 오답 시점까지 기록해 새로고침 후 비용을 다시 검증합니다. 서버·계정·기기 간 동기화는 없습니다.
- 정적 학습 게임이므로 개발자 도구로 데이터와 정답을 볼 수 있습니다. 경쟁형 anti-cheat를 제공하지 않습니다.

## 라이브러리

상단 **라이브러리** 또는 `#library`에서 전체 182종·군 / 209개 병원체 기록을 열람합니다. 이름·한글명·표현형 검색, 세균·진균·바이러스·기생충 분류와 18개씩 페이지 전환을 제공합니다. 기록을 열면 기존의 분류·형태·진단·약제 반응·적용 조건·근거 자료를 확인할 수 있습니다.

**약제 도감**은 약제 80개의 이름·계열·기전 검색과 계열 필터를 제공합니다. **발견 기록**은 직접 동정한 기록의 최고점·동정 횟수와 발견 진행률을 보여줍니다. 라이브러리 열람 자체는 동정실 라운드·점수·Archive를 변경하지 않습니다. 기존 `#archive`, `#drugs` 주소도 라이브러리의 해당 분류로 연결됩니다.

## 카드와 재사용 도감 DB

상단 **카드 도감** 또는 `#cards`에서 **병원체·표현형 209장과 약제 80장, 총 289장**을 같은 임시 디자인으로 열람합니다. 전체·세균·진균·바이러스·기생충·약제 분류, 이름·표현형·계열·핵심 요약 검색, 내성 표시 필터와 약제 계열 필터를 제공합니다. 라이브러리와 카드 도감은 24장씩 작은 카드로 모아 보여주며, 모바일은 2열이고 데스크톱은 기본 폭 약 190px의 다열 격자입니다. 카드 도감에서 목록 밀도를 160/190/220px 기준으로 바꿀 수 있습니다. 카드를 누르면 하나를 확대하고 현재 페이지의 이전·다음 카드를 넘깁니다.

앞면은 **대표 임상상·환자/노출 맥락·치료 선택을 바꾸는 특징**을 담은 한두 문장, **뒷장**은 상세 생물학·진단·질환·내성·약제 반응·적용 조건·근거를 담습니다. 앞뒤가 같은 2:3 크기이며 3D 회전으로 뒤집습니다. 확대 카드의 뒷면은 임상 / 약제·대상 / 기호 / 근거 탭으로 나누고 각 내용만 내부에서 스크롤합니다. 마우스 위치에 따라 약간 기울어지고, 모바일에서는 카드 표면을 좌우로 쓸어 뒤집거나 아래 버튼을 누릅니다. 모션 감소 설정에서는 움직임을 줄입니다. MRSA·VRE 등 이름이 붙은 내성은 공통 카드의 우상단 대각선 띠로 표시합니다. 분야별 색상과 SVG 기호는 재사용하며, 중앙 그림은 나중에 교체할 임시 기호입니다. 약제 경로는 기존 기록에 명시된 값만 사용하고 미지정은 `—`로 표시합니다.

| 영역 | 기본 360×540px 기준 |
| --- | --- |
| 전체 | 2:3 비율, 작은 화면에서는 비례 축소 |
| 이름 | 위쪽 변 중앙 |
| 경로 | 좌상단 약 40px 배지 |
| 그림 | 상·중단 약 296×296px 사각 창 |
| 계통 | 그림/텍스트 경계 약 29px 띠 |
| 핵심 요약 | 중·하단 약 144px, 한두 문장 |
| 기호 | 양쪽 세로 레일, 기호 약 14px |
| 내성 | 우상단 대각선 띠 |
| 뒷장 | 동일 비율 안에 상세 설명·출처, 내용 영역 스크롤 |

병원체의 왼쪽은 주요 친화 장기, 오른쪽은 해당 기록에 효과 있는 약제입니다. 약제의 왼쪽은 활성·요법 포함 기록이 있는 병원체 계통, 오른쪽은 R·비활성이 명시된 계통입니다. 계통 내 표현형별 판정이 다르면 양쪽 모두 켜질 수 있으며 세부 기록은 기호 설명과 뒷장에 나옵니다. `OUTSIDE_REGIMEN`은 무효로 집계하지 않습니다. 장기는 폐·신경계·혈류·심장/판막·피부·소화기·요로·간/담도·뼈/관절·눈 기호로, 약제는 약통/캡슐·주사기와 짧은 약제 약어로 구분합니다. 약제 카드의 병원체군은 포도알균·사슬알균·장알균·장내세균목·비발효균·기타 세균·진균·바이러스·기생충의 9개 고정 슬롯입니다. `src/card-models.mjs`가 DB를 카드 속성에 연결하고 `src/card-gallery-ui.mjs`가 목록을 제공합니다. `src/card-inspector.mjs`가 확대·이전/다음·요법 기준 선택을 담당합니다. `src/reference-card.mjs`와 `src/reference-card.css`가 공통 틀이며 `summary`와 `back`을 주입합니다. 그림은 `artwork: { src, alt }`, 장식 프레임은 `--card-frame-image`로 교체합니다.

### 편집 원본과 생성 데이터

요약은 분류·구조·작용점 나열보다 임상 특징을 먼저 씁니다. 병원체는 대표 감염·숙주·노출·합병증, 약제는 주된 사용처와 중요한 사용 한계, 내성 변형은 같은 감염에서 달라지는 약제 선택을 담습니다. 생물학·작용기전의 상세 설명은 뒷장의 기존 섹션에 둡니다.

**182종·군의 기본 요약, 209개 표현형·임상형의 앞면 요약, 80개 약제 요약**을 채웠습니다. 다중 표현형 41개는 개별 요약을 직접 작성하며, 단일 기록은 병원체 공통 요약을 사용합니다. 이름이 붙은 내성은 별도 `resistance: { code, label }`로 저장합니다.

| 파일 | 편집 내용 |
| --- | --- |
| `content/cards/bacteria.json` | 86종·군 세균 요약 |
| `content/cards/fungi.json` | 23종·군 진균 요약 |
| `content/cards/viruses.json` | 42종·군 바이러스 요약 |
| `content/cards/parasites.json` | 31종·군 기생충 요약 |
| `content/cards/drugs.json` | 80개 약제 요약·추가 근거(`references`, `summarySourceIds`) |
| `content/cards/variants.json` | 41개 변형별 요약·내성 표시 |
| `scripts/seed.mjs`, `scripts/expansion/*.json` | 상세 의료 내용·감수성·임상 맥락의 기존 작성 원본 |
| `data/library-schema.json` | 재사용 도감 DB 스키마 |

`npm run seed:cards`가 편집 원본과 현재 `data/organisms.json`을 합쳐 **`data/library.json`**을 생성합니다. 전체 `npm run seed`와 빌드에도 생성 단계가 연결됩니다. 생성 JSON을 직접 고치지 말고 요약은 `content/cards/`, 의료 사실은 기존 seed·확장 원본을 편집하세요. 새 ID를 추가하면 요약 원본도 추가해야 생성할 수 있습니다.

`data/library.json`은 ID를 키로 쓰는 정규화된 JSON DB입니다.

- `pathogens[taxonId]`: 병원체 공통 이름·분류·요약·상세 섹션.
- `variants[recordId]`: 공통 병원체 참조 `pathogenId`, 표현형·임상형 요약, 내성 표시와 상세 차이.
- `drugs[drugId]`: 약제 이름·계열·요약·상세 섹션.
- `responses[recordId][drugId]`: 실제 약제 반응의 profile ID.
- `responseProfiles[profileId]`: 중복 없이 보관한 판정·기전·적용 조건·출처. ID는 내용에서 생성되므로 목록 순서에 의존하지 않습니다.
- `sources`, `panels`, `categories`, `interpretation`: 근거와 관찰 범위·판정 의미를 함께 제공.

`src/card-catalog.mjs`의 `createCardCatalog(db).pathogen(recordId)`와 `.drug(drugId)`가 앞면 요약과 뒷면 내용을 반환합니다. 변형의 상세 섹션은 같은 ID의 공통 섹션을 덮어쓰고, 나머지는 상속합니다. 게임용 `organisms.json`은 호환용 출력으로 유지되며 도감 정보는 별도 DB로 재사용합니다. 기존의 S/I/R·조건부 활성·문헌상 활성·요법 포함 여부와 적용 조건을 그대로 구분합니다.

## 의료 데이터의 의미

`data/organisms.json`이 플레이 데이터, `data/schema.json`이 확장용 JSON Schema,
`data/sources.json`이 근거 목록입니다. 핵심 seed, `scripts/sources.base.json`, `scripts/expansion/*.json`이 작성 원본이며 `npm run seed`로 병합합니다.
수동 JSON 수정은 seed 재생성 시 덮어써지므로 seed와 확장 패키지를 작성 원본으로 유지하세요. `npm run build`도 전체 조합·출처 검증을 수행합니다.

원본 `19 the medicine resource`는 **읽기 전용**으로 참고했습니다. 개인정보·학습 이력·원문 전체는 배포하지 않습니다.
`docs/source-audit.json`에는 참고한 파일의 상대 경로와 SHA-256을 기록합니다.
기존 spectrum의 `variable/conditional`을 S로 자동 매핑하지 않았습니다.

현재 검증의 한계와 미해결 문제는 [데이터 감사 기록](docs/data-audit-2026-09-30.md)에 정리했습니다. 출처 링크와 자동 테스트 통과가 모든 조합의 의학적 검증을 뜻하지 않습니다.

전체 데이터의 검토 상태는 **educational-draft**입니다. 세균 감수성 분야는 문헌 제약을 반영한 고정 교육용 분리주이고, 나머지 분야는 **명시된 감염·병기·숙주 조건에서 문헌 요법에 포함되는 약제**를 단서로 삼습니다. 구조·게임 테스트가 전문 임상 검토를 대신하지 않습니다.

`REGIMEN`은 표준·대안 요법의 구성 약제(병용·투여경로·선행검사 조건 포함), `OUTSIDE_REGIMEN`은 이 기록이 인용한 요법 목록에 없다는 뜻입니다. 후자는 비활성·내성·금기를 뜻하지 않습니다. 지지요법이 중심인 바이러스도 이 구분을 사용합니다. 게임 JSON은 호환성을 위해 약제 단서를 `susceptibility`에 저장하되 `observationType`, `basis`, `clinicalContext`로 의미를 명시합니다.
S/I/R의 의미 및 일부 조합의 추론 규칙은 EUCAST v16.1 (2026)을 따릅니다.
`I = Susceptible, increased exposure`; R 또는 CLSI Intermediate와 같지 않습니다.
배포 검증은 NA·빈 값·일반적인 “추가 AST 필요” 자리표시자를 차단합니다. S/I/R 근거가 없는 조합은 임의 판정 대신 적용 조건과 확인된 활성을 작성합니다. ACT는 고노출·병용·상승작용 등 명시된 조건에서의 활성입니다. ACTIVE/INACTIVE는 문헌 기반 항균 활성로 임상 S/I/R 범주와 구분합니다. Breakpoint 부재를 비활성으로 간주하지 않습니다. E. coli cefazolin은 요로 유래 감염 범위입니다.
개별 실제 균주를 대변하거나 임상 처방을 권고하는 데이터가 아닙니다.

MSSA/MRSA, MSSE/MRSE, E. faecalis/faecium VSE/vanA VRE, E. coli baseline/ESBL,
K. pneumoniae ESBL/KPC, P. aeruginosa non-DTR/DTR, E. cloacae inducible/derepressed AmpC를 포함합니다.
Glycopeptide 감수성, ESBL 이후의 비-β-lactam 결과 등은 해당 분리주의 설정이며 종/phenotype 전체의 보편적 결과가 아닙니다.

MIC와 breakpoint는 현재 모두 null입니다. 고급 모드는 의도적으로 비활성화했습니다.
활성화 전에는 약제·균종·감염부위·노출조건·표준·버전을 고정하고
실측/교육용 MIC 출처 및 수치 판정 테스트를 추가해야 합니다. ECOFF는 임상 breakpoint 대신 쓰지 않습니다.

새 데이터를 추가할 때:

1. 새 taxon/phenotype 조합에 고유 ID를 부여합니다. 기존 기록의 ID는 재사용하지 않습니다.
2. 해당 패널의 모든 힌트와 약제 조합을 전문 출처로 채웁니다. NA·빈 값은 금지합니다. S/I/R, 예상 내성, 조건부 활성의 근거를 구분하고 부위·노출·병용 제한과 해당 출처를 명시합니다. 근거를 확보하지 못한 조합은 데이터에 추가하지 않습니다.
3. 패널·분야·관찰 유형, 출처, 검토 상태, 해석 규칙을 입력합니다. 요법 단서는 명확한 clinicalContext와 해당 상황의 표준·대안요법 근거를 요구합니다. 종의 특성과 분리주의 내성을 분리합니다.
4. 동일한 힌트는 본문을 동일하게 유지합니다. 관찰 본문이 바뀌면 정보량 계산도 바뀝니다.
5. 데이터 버전을 올리고 seed와 테스트를 실행합니다. 데이터 버전 변경 시 진행 중 라운드는 초기화되며 유효한 Archive ID는 유지합니다.
6. 전문가 검토 후에만 reviewStatus를 expert-reviewed로 변경합니다.

## 항생제 선택 모드

상단 **항생제 선택** 또는 `#treatment`에서 플레이합니다. 성인 임상 사례 32문항: 증상 → 경험적 항생제 10, 병원체 → 표적 항생제 12, 질병 → 치료 요법 10. 전체 혼합/트랙별 무작위 최대 10문항 세트를 제공합니다. 문항 및 선택지 순서를 섞으며 같은 세트에서 문항을 반복하지 않습니다.

- 감염 부위·중증도·숙주·감수성·내성 기전·약제 가용성을 명시하고, 제시된 선택지/지침 조건에서 답을 고릅니다. 동정실의 S/I/R 타일에서 치료 정답을 자동 추론하지 않습니다.
- 제출 후 변경 없이 채점하고 정답 이유, 선택지별 해석, 요법·투여 조건, 인정되는 대안, 재평가·치료 축소, 핵심 판단과 출처를 공개합니다.
- 답을 직접 확인한 문항은 정답률에서 제외하고 복습 목록에 남깁니다. 오답 또는 답 확인 후 나중에 직접 맞히면 복습 목록에서 빠집니다.
- 트랙/범위별 세트와 오답 기록을 `pathopedia.treatment.v1`에 별도 저장합니다. 새로고침·동정실 이동 후 이어 풀 수 있습니다. 동정실 Archive와 점수는 기존 저장 키를 사용합니다.
- 근거 21개 문서의 기관·출판/지침 연도·지역·관련 절·확인일을 기록합니다. IDSA 2026 AMR, 2025 cUTI, WHO 2025 수막염, ESC 2023, CDC STI, SHEA/IDSA CDI 및 국내 요로감염 지침 등을 사용합니다. 오래된 지침의 지역 내성률을 현재 수치로 간주하지 않습니다.
- 전체 문항은 **교육용 초안 / 전문 임상 검토 전**입니다. 문헌 확인과 구조·게임 테스트가 임상 전문가 검토를 대신하지 않습니다. 해외 신약의 국내 허가·공급 및 모든 실제 환자의 투여 조건을 보장하지 않습니다.

작성 원본은 `scripts/seed-treatment.mjs`, 플레이 데이터는 `data/treatment-questions.json`입니다. `npm run seed:treatment`로 재생성하고 `npm run validate:treatment`로 필수 임상 조건·선택지·해설·근거 참조를 검사합니다. `npm run seed`도 두 데이터 세트를 함께 재생성합니다. 문항 변경 시 치료 datasetVersion을 올려 이전 답/선택지에 의한 오채점을 방지합니다.


금색은 특정 임상 상황에서 근거가 연결된 우선요법, 흰색은 그 외 유효·요법 포함 기록, 약제 오른쪽의 붉은색은 R·비활성, 회색은 비해당·기록 없음입니다. 병용·증가 노출·판정 혼재 조건은 작은 파란 점으로 덧붙입니다. 우선요법은 `S` 결과에서 추정하지 않습니다.

`content/cards/therapies.json`에 31개 임상 상황의 `recordIds, context, drugIds, excludedDrugIds, sourceIds, note, combination`을 분리해 작성했고 생성 DB의 `therapyContexts` 및 기록별 `therapyIds`로 연결합니다. 확대 화면에서 기준을 선택합니다. 약제 카드의 전체 보기에서 금색은 그 계통에 우선요법 대상 임상형이 있다는 뜻이며 모든 종·표현형·감염 부위의 일차약이라는 뜻은 아닙니다. 미지정 우선순위는 알 수 없음이며 흰색을 곧 2차 약제로 읽지 않습니다.

내성형 겹쳐 보기는 같은 병원체 ID의 기본형과 내성형을 한 목록으로 묶습니다. 묶음마다 펼치기/접기를 지원하며, 전체 스위치를 끄면 모든 카드를 개별로 표시합니다. 검색·분류·발견 기록에서 제외된 카드는 묶음에 포함하지 않고, 확대 창에서 기본형·내성형을 선택할 수 있습니다. 보기 설정은 로컬에 보관합니다.

## 버전

SemVer `v 0.0.0` 형식. 작은 수정은 patch, 기능 묶음은 minor 증가 후 patch를 0으로 초기화합니다.
앱 버전은 package.json 및 화면에 표시되며 CHANGELOG.md에 변경 내용을 기록합니다.

## PWA와 아이콘

현재 v 0.14.1. 홈 화면 설치용 manifest와 192/512px 아이콘, iOS용 180px 아이콘을 제공합니다.
지원 브라우저에서 사이트 설치 또는 홈 화면에 추가할 수 있습니다.
앱 식별자는 `/pathopedia/`로 고정합니다. `id`는 manifest 디렉터리가 아닌 시작 URL의 origin 기준으로 해석되므로 `./`를 쓰면 같은 도메인의 다른 앱과 겹칠 수 있습니다.
설치 manifest는 온라인에서 최신 정보를 우선 받고, 연결이 없으면 마지막 정상 캐시를 사용합니다. 이전 버전이 열려 있으면 ‘업데이트 적용’ 후 탭을 다시 열어 설치합니다.
첫 온라인 방문에서 캐시 설치가 완료되면 오프라인에서도 게임·Archive를 사용할 수 있습니다.
외부 웹폰트를 불러오지 못하면 시스템 글꼴을 사용합니다.
업데이트는 알림의 ‘업데이트 적용’을 눌러 반영하며 현재 진행 기록은 저장합니다.
앱 파일을 변경해 배포할 때 package.json, src/app.mjs와 sw.js 버전을 함께 올립니다.

아이콘 원본과 정확한 생성 프롬프트는 assets/에 보관합니다. OpenAI 내장 image_gen으로 생성했습니다.

## 게임 화면

v0.3.0부터 PokeQuiz Wiki Quiz의 자리 채우기 동작을 적용합니다.
9개 정보 타일과 최대 16개 약제 버튼이 같은 화면에 있고, 클릭하면 칸의 내용만 바뀝니다.
긴 정보는 공개한 칸을 다시 눌러 추가 비용 없이 전체를 봅니다.
검사 기록 및 정답 후 전체 organism record는 dialog로 열립니다.
데스크톱에서는 화면 높이에 맞춘 고정 보드이며, 작은 모바일 화면/높은 확대 배율에서는
글자를 과도하게 줄이지 않도록 세로 스크롤 배치를 사용합니다.
